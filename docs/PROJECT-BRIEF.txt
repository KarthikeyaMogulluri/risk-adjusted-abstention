1.  WHAT KIND OF PROJECT THIS IS
================================================================================

This is an ACADEMIC RESEARCH PAPER, not a software product.

The output is a written paper plus a small reproducible code artifact. The
code exists only to produce the numbers in the paper. Nobody will use the
code as a tool, and it does not need to be beautiful, packaged, marketed or
maintained. This is worth stating plainly because the instinct from the other
projects in this vault is to build something usable. Resist it here. A paper
that is 60% polished code and 40% argument is a failed paper.

Research type:     Empirical + analytical (mixed)
Field:             Software Engineering / Distributed Systems / AIOps
Sub-area:          Reliability engineering, selective prediction, FinOps
Paper class:       Short paper or workshop paper FIRST, full paper SECOND
Target length:     4-6 pages (short) or 8-10 pages (full), venue decides
Human dependency:  Almost none until submission (see section 8)

Why "short paper first" and not the full thing:

A full empirical paper requires running an LLM agent across 700+ labelled
failure cases with ablations. That is four to eight weeks of work and real
API spend. The stated timeline is days. So the first paper answers only the
premise question, which requires NO agent runs at all - it is pure data
analysis over telemetry that already exists in public benchmarks. It is
cheap, honest, publishable, and it is the falsification gate for the larger
study. If the premise fails, you learn it in three days instead of three
months.

2.  THE PROBLEM STATEMENT
================================================================================

TITLE

  Risk-Adjusted Abstention for LLM-Assisted Root Cause Analysis: Making the
  Autonomy Threshold a Function of Error-Budget and Cost Stakes in Kubernetes

STATEMENT

  Kubernetes operations teams increasingly delegate incident diagnosis to
  LLM-based agents, and the mechanism that makes this safe is a confidence
  gate: the agent proposes a root cause with a confidence score, and a
  threshold decides whether it acts autonomously or hands over to a human.

  Prior work has concentrated on making that confidence score well
  calibrated, and has treated the threshold itself as a fixed hyperparameter
  applied uniformly across incidents.

  This assumption is false in production. The cost of an incorrect autonomous
  action on a low-traffic internal service and on a revenue-critical payment
  path differ by orders of magnitude. A single threshold is therefore
  simultaneously too conservative on cheap incidents and unsafe on expensive
  ones.

  This work reframes RCA autonomy as risk-sensitive selective prediction over
  a three-way action space - act, assist, escalate - derives the abstention
  threshold per incident from a loss function over error-budget burn,
  infrastructure and revenue exposure, engineer time and inference cost, and
  estimates every stake term from cluster telemetry rather than from
  unavailable business-cost labels.

  Evaluation on public microservice RCA benchmarks measures cost-weighted
  regret against a perfect-information oracle and against the strongest
  hindsight-tuned fixed threshold, with a sensitivity sweep over the cost
  model.

THE ONE CLAIM (if you can only say one thing)

  The abstention threshold is not a constant. It is a function of what the
  incident is worth, and treating it as a constant produces regret that grows
  with the variance of stake across the incident population.

FALSIFICATION CONDITION (write this into the paper before any result exists)

  If the stake distribution across the benchmarks proves near-uniform, the
  derived threshold collapses into the fixed baseline and the central
  hypothesis is refuted. This is tested FIRST and it is a real gate on the
  rest of the work.

3.1  DATA REQUIREMENTS
--------------------------------------------------------------------------------

You build no testbed and inject no faults. Everything comes from published
benchmarks. Two independent datasets minimum - a stake distribution shown on
one dataset is an artifact, shown on two it is a finding.

  PRIMARY      RCAEval  (RE1 / RE2 / RE3)
               ~735 labelled failure cases
               Systems: Sock Shop, Online Boutique, Train Ticket
               Contains: per-service metrics, traces, logs, ground-truth
               root cause, fault type and injection time
               Why: peer-reviewed as a benchmark, pip-installable

  SECOND       RCA100 / AIOps2025
               500+ expert-labelled cases
               Systems: HipsterShop, OpenTelemetry Demo Store
               Why: different traffic shape, tests generality

  OPTIONAL     Cloud-OpsBench
               Agentic-RCA framing that matches the paper's framing
               Use only if days 1-2 go faster than planned

WHAT EACH CASE MUST CONTAIN for the stake estimator to work:

  [ ] Per-service metric time series - CPU, memory, request rate, error
      rate, latency percentiles
  [ ] Replica or pod count over time (for replica-seconds -> cost)
  [ ] Service dependency graph or call graph (for blast radius)
  [ ] Ground-truth fault label - which service, what fault, when

  RISK: if a dataset lacks replica counts, cost must be proxied from CPU and
  memory usage instead. Check this on Day 1 before building anything.

================================================================================
7.  ERRORS TO PRE-KILL
================================================================================

Each of these is a way the paper dies. Each already has a counter built
into the plan above.

  "Your cost model is arbitrary"
      -> OpenCost + FOCUS + published prices. And note that the RANKING is
         invariant to the price constant - the multiplier cancels out, so
         only ordering matters.

  "You cherry-picked SLOs to manufacture variance"
      -> Uniform SLO across every service, declared before the analysis.

  "This is just PACE-LM with extra steps"
      -> You CONSUME calibration and CONTRIBUTE the threshold. Cited in
         related work, never claimed as yours.

  "One dataset, one artifact"
      -> Two independent populations with different traffic shapes.

  "You beat a strawman baseline"
      -> The opponent is the hindsight-tuned optimal fixed threshold.

  "Accuracy looks about the same"
      -> Primary metric is cost-weighted regret. Accuracy is reported and
         explicitly argued to be the wrong lens.

  "The gains vanish under different assumptions"
      -> Sensitivity sweep, with the breakdown point stated openly.

  "Simulated confidence is not real confidence"
      -> Labelled as simulation in the section heading. The full agent
         study is named as the follow-up. Do not oversell. Reviewers
         forgive limited scope; they never forgive spin.
